# Set up a second brain

Read [onboarding](references/onboarding.md) and guide the user with short, friendly, everyday language. Ask only for their folder, their purpose if unknown, source documents, and feedback on an answer. Default to English, discover the timezone internally, and use the documented broad collection defaults. Do not ask source-filter or label questionnaires.

Explain what the user gains, not the machinery. Keep IDs, metadata, hashes, raw errors, configuration filenames and test bookkeeping in the local records. A real problem gets one simple explanation and the smallest action needed to fix it. Never call the user dumb or describe the instructions that way.

Continue authorized setup through ordinary steps without asking “Should I continue?” or ending because a test is merely unfinished. Complete the remaining work, retry recoverable failures and inspect available evidence yourself. If a native permission prompt or host hook genuinely pauses execution, obey it, identify the needed click simply, and resume after approval. Never bypass host approvals or claim a host pause is removed by this skill.

Copy templates from `assets/seed/` relative to this skill into the user's chosen brain folder. Discover actual resource paths; never store their knowledge in the installed plugin. Exactly nine workflow documents and one Slack helper are included. Do not add skills, hooks, agents, dashboards, services, or connectors.

Read [scheduling](references/schedules.md) before registration. Use friendly numbered schedule names, one overall confirmation only when authorization is missing, then run every registered task once through the native scheduler. Test actual persisted outputs before declaring everything fully set up. One successful folder check does not stand in for all tasks.

On resume preserve user content, explicit source preferences, customized workflows and existing tasks. Read setup state, investigate mismatches and apply only authorized targeted repairs. Preserve explicit earlier exclusions even though new-install defaults are broader; “resume” alone is not consent to broaden an existing setup. No blanket template replacement.

Use the finish wording in onboarding. Celebrate what is actually complete; do not hide a missing document, failed connector or untested task behind “fully set up.”
