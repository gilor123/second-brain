# health-check

Check workflow invariants and wiki coherence; make only unambiguous mechanical repairs.

## Read first

Read `.claude/CLAUDE.md`, `wiki/.claude/CLAUDE.md`, `wiki/meta/INDEX.md`, and `wiki/meta/sources.json`. Collectors also read `raw/.claude/CLAUDE.md`. All paths are brain-root-relative. Use configured timezone and actual tested tool bindings, never guessed tool names.

## Zone rule

Read raw; write wiki bookkeeping/reports, engine lock, and verified workflow restores. Never edit raw, source settings, schedules, scripts or charters.

## Procedure


1. Acquire the engine lock. For charter/configuration differences, consult the intentional setup-edit record and personalized baseline. A personalized purpose line or legitimate user edit is not a broken invariant. Read the content and log to resolve ordinary differences yourself; if an older setup has no edit record, compare changes to its recorded purpose/name/language and document clearly matching personalization in the derived setup record; do not ask whether the user edited a file unless a substantive unexplained conflict requires their decision. Never overwrite a charter to match the pristine seed. Check each of the nine workflow documents for purpose, Zone rule and Self-improvement contract; inspect body consistency with its contract and engine charter. The source health workflow has its own narrower reporting role. Scripts are read-only dependencies, not self-improving documents.
2. For a malformed or boundary-breaking workflow, locate an exact validated predecessor in `maintenance/archive/workflow-versions/`. Verify checksum, recorded relative path and actual invariants; a backup's existence alone does not prove it is valid. Restore only that workflow. If no valid predecessor exists, flag it as blocked in the report/log; do not fabricate a repair or execute the damaged workflow. Preserve the failed version as evidence.
3. Check internal links including archived sources, INDEX drift, page shape, one-way links, orphan/duplicate candidates, uncited claims, stale claims, unresolved questions and wiki/source contradictions. Actual source citations must support the claims, not just point to an existing file.
4. Auto-fix only unambiguous bookkeeping: a clear renamed target, missing index entry for an existing page, a justified backlink or trivial heading order. Flag missing content, merges, uncertain link targets and substantive contradictions. Do not invent sources or create knowledge to make a check pass.
5. For a curated-source discrepancy, quote the competing evidence and propose a specific correction in the report for user review; never apply it to raw. Inspect collection gaps and recorded schedule/connector failures as observations, without changing tasks or settings.
6. Write/merge `wiki/digests/YYYY-Www-health-check.md` with run ID, checked/restored/mechanically-fixed/flagged counts and concrete evidence. Update INDEX/log. Release the owned lock.


## Self-improvement contract

Mechanical repairs and verified restores only. No raw edits, semantic rewrites, invented citations, new skills or settings changes. Invalid workflows without recoverable predecessors are flagged, never executed. Preserve evidence and log all repairs.
